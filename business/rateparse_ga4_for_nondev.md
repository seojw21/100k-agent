# RateParse GA4 — 비개발자용 설명서

> 코드 수정은 에이전트/개발자가 함. 창업자는 **배포 확인 + GA 화면 보기**만 하면 됨.

---

## 이게 뭔 소리였나? (비유)

| 비유 | RateParse |
|------|-----------|
| 가게 앞 **방문 카운터** | 지금까지 GA가 보던 것 (몇 명 왔는지) |
| 계산대·가입·업로드 **벨** | 이제 넣을 **이벤트** (누가 뭘 했는지) |

방문만 알면 “37명 왔다”만 보임.  
벨을 달면 “가입 2 / 파싱 1 / 결제 시도 0”처럼 **진짜 실험 숫자**가 보임.

**파일 위치, logEvent** 같은 말은 개발자 일. 외울 필요 없음.

---

## 역할 분담

| 누가 | 뭘 하나 |
|------|---------|
| **에이전트/개발자** | 사이트 코드에 “벨” 달기 → 빌드 → (요청 시) 배포 |
| **당신** | 배포된 사이트에서 한 번 눌러보기 + GA에서 숫자 확인 |
| **안 해도 됨** | TypeScript 수정, firebase.ts 직접 편집 |

## 코드에 달린 벨 목록 (이름만 알면 됨)

| 이름 (영어) | 뜻 (한국어) |
|-------------|-------------|
| `cta_click` | “무료 시작” 같은 버튼 클릭 |
| `sign_up` | 신규 가입 |
| `login` | 로그인 |
| `file_select` | 운임표 파일 선택 |
| `parse_start` | 파싱 시작 |
| `parse_success` | 파싱 성공 ← **제일 중요** |
| `parse_fail` | 파싱 실패 |
| `search_lane` | 레인 검색 |
| `quota_exceeded` | 한도 초과 |
| `begin_checkout` | PayPal 구독 시작 |
| `purchase` | PayPal 승인 완료 (결제 의사) |
| `subscribe_error` | 결제 버튼 오류 |

## 당신 할 일 체크리스트

### 1) 배포됐는지 확인

- 코드만 고치고 **인터넷 rateparse.xyz에 안 올리면** GA에 안 보임.
- 배포는 보통: `firebase deploy` 또는 쓰던 배포 방법.
- 모르겠으면 에이전트에게: **「RateParse 프론트 배포해줘」**

### 2) 본인이 테스트 (배포 후 5분)

1. 시크릿/다른 브라우저로 https://rateparse.xyz 접속  
2. **Start free with 3 sheets** 클릭  
3. (가능하면) 가입 또는 로그인  
4. (가능하면) 샘플 시트 업로드  

→ 이게 `cta_click`, `sign_up`/`login`, `parse_*` 벨을 울림.

### 3) GA에서 보기 (30분~24시간 걸릴 수 있음)

1. https://analytics.google.com 로그인  
2. RateParse 속성 선택 (Measurement ID `G-JYQ1V2V95M` 쪽)  
3. 왼쪽 **보고서 → 실시간**  
   - 지금 테스트 중이면 “이벤트 이름별”에 위 이름들이 보임  
4. 하루 뒤 **보고서 → 참여도 → 이벤트**  
   - `parse_success`, `sign_up` 횟수 확인  

### 4) “주요 이벤트”(전환) 표시 — 한 번만

이벤트가 목록에 나타난 뒤:

1. 관리(톱니) → **이벤트**  
2. `sign_up`, `parse_success`, `begin_checkout`, `purchase` 찾아서  
3. **주요 이벤트로 표시** ON  

이후 개요에서 “전환”으로 보이기 쉬움.

### 5) 7/17 중간점검에 적을 것

GA 개요의 “활성 사용자 37” 대신:

- `sign_up` 몇 번  
- `parse_success` 몇 번  
- `purchase` 몇 번  

이 세 줄이 실험 판정에 맞음.

## 자주 하는 오해

| 오해 | 사실 |
|------|------|
| 내가 코드를 짜야 한다 | **아니요.** 이미/앞으로 에이전트가 함 |
| GA 화면만 설정하면 된다 | **반만 맞음.** 코드 배포 없이는 방문만 계속 보임 |
| 바로 개요에 숫자가 바뀐다 | **실시간**은 빨리, **일반 보고서**는 몇 시간 걸릴 수 있음 |
| purchase = 무조건 입금 완료 | PayPal 창에서 승인 완료 신호. 최종 구독은 웹훅/PayPal 관리 화면과 대조 |
